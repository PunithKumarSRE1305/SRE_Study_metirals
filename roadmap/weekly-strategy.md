# Weekly strategy

## Default shape

| Day | Mode | ~Minutes | Output |
| --- | ---- | -------: | ------ |
| 1 | Theory | 120 | Mental model + notes |
| 2 | Theory + examples | 120 | Worked examples |
| 3 | Hands-on | 120 | Lab evidence |
| 4 | Troubleshooting | 120 | A diagnosed failure |
| 5 | Advanced / internals | 120 | Deeper "what really happens" |
| 6 | Project | 120 | Something that still exists tomorrow |
| 7 | Revision + assessment | 90–120 | Log + exam if unlocked |

Weekly planned hours: **10–14**.  
Day 7 can be 60 minutes if no assessment is unlocked.

## If work explodes

Priority order:

1. Keep **one** 90-minute block so the chain does not break
2. Drop Day 5 stretch, not Day 3 lab
3. Slide assessment to the next free evening
4. Never stack two assessments on the same night

## If you are ahead

Do **not** pull next month's Kubernetes forward.  
Do: a failure drill from [`../29-incident-simulations/`](../29-incident-simulations/), or deepen a weak area, or advance the portfolio version that is *already unlocked*.

## Weekly review questions (10 minutes)

1. What can I do this Sunday that I could not do last Sunday?
2. What did I memorize instead of understand?
3. Did I log hours honestly?
4. Is anything 🔴?
5. What is Day 1 next week?

Update [`../progress/weekly-tracker.md`](../progress/weekly-tracker.md) from evidence.
